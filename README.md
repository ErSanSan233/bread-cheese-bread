# 两面包夹芝士（bread-cheese-bread）

**在已有录音的指定位置，插入一段以同一音色合成的旁白。**

本项目接收音视频素材（自动提取音频），由使用者指定三个时间点：采样起点 A、采样终点 C、插入点 B，并满足 A < B < C。程序截取 A–C 区间的音频作为音色与语气参考，据此合成使用者输入的旁白文本，最终输出：

```
[A→B 原声] + [合成旁白] + [B→C 原声]
```

即「两片原声（面包）夹一片合成旁白（芝士）」。除插入点外，原始片段不做任何修改。

全部计算在本机完成，不产生外部网络请求。

## 工作原理

以一段 90 秒的录音为例：

```
原始素材

0s          10s         25s                     60s        90s
|            |           |                       |          |
|            A           B                       C          |
|            |<------ 采样区间 A–C（50s）------->|          |


成品（53.4s）

|===== 原声 A→B =====|=== 合成旁白 ===|===== 原声 B→C =====|
      10s → 25s           3.4s             25s → 60s
     （原样保留）     （由 A–C 音色合成）     （原样接回）
```

三个时间点的定义：

| 标记 | 名称 | 作用 |
|---|---|---|
| **A** | 采样起点 | 与 C 共同界定参考区间 |
| **C** | 采样终点 | A–C 决定合成所用的音色与语气 |
| **B** | 插入点 | 旁白插入位置，须满足 A < B < C |

程序以 A–C 区间为参考，学习其中的音色、语速与语气，据此朗读使用者输入的文本，并插入至 B 点。成品由三段构成：A→B 原声、合成旁白、B→C 原声。

参考音频自身携带语气，合成结果与之对应：A–C 区间为平稳讲解，输出同样平稳；区间本身带情绪，输出亦保留该情绪。因此，参考区间的选取对最终效果的影响高于其余任何参数。

## 功能边界

本项目不覆盖以下场景，安装前应先行确认：

- **视频时间轴对齐。** 仅生成音频片段并插入，不涉及画面。需卡点时请在剪辑软件中另行处理。
- **实时变声。** 不支持实时的人声转换。
- **超长文本合成。** 数十字的输入最稳定；上百字建议分段生成。
- **从劣质样本还原高质量音色。** 参考区间含背景音乐、削波或长静音时，输出会保留同类问题。界面会给出警告，但不阻止执行。
- **随仓库分发模型权重。** 权重由使用者自行下载，见[安装部署](#安装部署)。

## 环境要求

### 硬件与系统

| 项 | 要求 | 说明 |
|---|---|---|
| 机型 | Mac，**Apple Silicon**（M1/M2/M3/M4 系列） | 合成使用 Apple GPU（MPS）；质检依赖 MLX，仅 Apple Silicon 可用 |
| 内存 | ≥ 16 GB | 模型权重本身 3.2 GB，加载后另需推理开销；8 GB 机器易内存不足 |
| 磁盘 | ≥ 20 GB 可用 | 构成见下表 |
| 系统 | macOS | 脚本与路径按 macOS 编写 |

磁盘占用构成：

| 内容 | 体积 |
|---|---|
| 合成模型（IndexTTS2）权重 | ≈ 4.3 GB |
| 质检模型（whisper，可选） | ≈ 3 GB |
| Python 环境与依赖 | ≈ 1 GB |

> **Intel Mac**：合成部分理论上可运行于 CPU，但耗时不可接受；质检完全不可用。本文档不覆盖该情形。

### 素材要求

需准备一段自有录音作为输入：

- **干净人声**：单人说话，无背景音乐，无明显电流声或喷麦
- **长度**：采样区间建议 10–20 秒，整段素材应长于该区间
- **语气匹配**：参考区间与待补语句的情绪应尽量接近
- **授权**：见[隐私与合规](#隐私与合规)

## 安装部署

项目自身的代码量很小，主要工作在于准备两个外部依赖：合成模型与语音识别模型。共五步。

### 第 1 步：安装 ffmpeg

ffmpeg 用于抽取音轨、切片与拼接。

```bash
brew install ffmpeg
```

验证：

```bash
ffmpeg -version | head -1
```

> mp3 导出依赖 `libmp3lame` 组件，Homebrew 版本默认包含。若缺失，其余流程不受影响，仅不产出 mp3 文件。
> 检查命令：`ffmpeg -hide_banner -encoders 2>/dev/null | grep -i mp3`

### 第 2 步：创建 Python 环境

创建独立环境，避免将包装入系统 Python。此处以 conda 为例。**该环境仅安装 Web 层依赖，不安装任何 AI 相关包。**

```bash
conda create -n bcb python=3.11 -y
conda run -n bcb python -m pip install fastapi uvicorn python-multipart numpy
```

> 无 conda 时可改用 venv：`python3.11 -m venv .venv`，并在第 5 步将 `BCB_PY` 指向其解释器。
>
> 在受限沙箱中安装时，conda 清理临时文件可能触发批量删除守卫而失败。若报错包含
> `SAFE_DELETE_BULK_CONFIRM_REQUIRED`，先执行
> `export CODEBUDDY_SAFE_DELETE_BULK_THRESHOLD=1000000` 后重试。

### 第 3 步：安装合成模型

合成使用 **IndexTTS2**（B 站开源），为本项目唯一的大体积依赖。需注意：**它必须安装在独立环境中，不可与第 2 步的环境混用。**

操作流程以 IndexTTS2 官方仓库说明为准，大致如下：

```bash
# 获取源码
git clone <IndexTTS2 官方仓库地址>
cd index-tts

# 创建独立虚拟环境（Python 版本须为 3.10 或 3.11）
python3.11 -m venv .venv
.venv/bin/python -m pip install -e .
```

随后将官方模型权重下载至 `checkpoints/` 目录。该目录至少应包含：

```
config.yaml      gpt.pth          s2mel.pth        codec.pth
wav2vec2bert_stats.pt              feat1.pt         feat2.pt
pinyin.vocab     multilingual_zh_ja_yue_char_del.tiktoken
qwen0.6bemo4-merge/                hf_cache/
```

权重文件名与体积随版本变化，下载方式以官方仓库为准。主权重的 HuggingFace 仓库名为 `IndexTeam/IndexTTS-2.5`。

`hf_cache/` 一项容易被忽略：w2v-bert-2.0、semantic_codec、bigvgan、campplus 四个辅助模型
（合计约 5 GB）不包含在官方权重包里，首次加载模型时才联网下载，会阻塞第一次合成。
国内网络建议提前走镜像预取，参见上文的 `HF_ENDPOINT` 设置。

安装完成后验证：

```bash
.venv/bin/python -c "import torch; print(torch.__version__, torch.backends.mps.is_available())"
```

输出为版本号后跟 `True`，表示 Apple GPU 可用。此命令约需一分钟。

> **国内网络**：直连 `huggingface.co` 会触发 SSL 验证失败。下载前设
> `export HF_ENDPOINT=https://hf-mirror.com`；pip 安装可加
> `-i https://pypi.tuna.tsinghua.edu.cn/simple`。
>
> **若此步受阻**：属于 IndexTTS2 自身的安装问题，请查阅其官方仓库的安装说明与 issue。

### 第 4 步：安装质检模型（可选）

质检流程为：合成完成后，用语音识别将合成音频转写为文本，与输入稿逐字比对，以发现读字错误。

```bash
pip install mlx-whisper
```

并将 `whisper-large-v3-mlx` 权重下载至本地任意目录。

该步可跳过，仅影响质检报告的生成。建议先完成其余步骤，流程跑通后再补装。

### 第 5 步：配置路径

```bash
cp bcb.env.example bcb.local.env
```

编辑 `bcb.local.env`，**至少填写两行**：

```bash
BCB_TTS_PY=/path/to/index-tts/.venv/bin/python      # 第 3 步环境的 python
BCB_TTS_CKPT=/path/to/index-tts/checkpoints         # 第 3 步下载权重的目录
```

`bcb.local.env` 不纳入版本控制。代码中不含任何硬编码路径；ffmpeg 与 mlx_whisper 只要在系统 PATH 中可检索即自动使用，无需填写。

全部可配置项：

| 变量 | 必需 | 作用 |
|---|---|---|
| `BCB_TTS_PY` | ✅ | 合成模型环境的 python 解释器 |
| `BCB_TTS_CKPT` | ✅ | 合成模型的权重目录 |
| `BCB_TTS_CWD` | | 合成模型源码目录，一般为权重目录的上一级 |
| `BCB_FFMPEG` / `BCB_FFPROBE` | | 不在系统 PATH 中时填写 |
| `BCB_MLX_WHISPER` | | mlx_whisper 路径（不配置则跳过质检） |
| `BCB_WHISPER_MODEL` | | whisper 权重目录 |
| `BCB_PY` | | Web 层解释器，默认自动检索 conda 的 `bcb` 环境 |
| `BCB_PORT` | | 服务端口，默认 8733 |

### 启动

```bash
./run.sh
```

脚本会先执行自检再启动服务，缺失项直接输出：

```
  ffmpeg             ✓
  IndexTTS2 解释器      ✓
  IndexTTS2 权重       ✓
  whisper 程序         ✓
  whisper 权重         ✓
缺失（必需）: 无
→ http://127.0.0.1:8733
```

浏览器访问 http://127.0.0.1:8733。界面顶部同样显示依赖状态。按 `Ctrl+C` 停止服务。

## 使用流程

建议先以数分钟以内的短素材验证流程。

**1. 导入**

将文件拖入页面虚线框，或点击选择文件。支持视频，音频轨道自动提取。导入过程显示进度，完成后显示波形。

**2. 设置 A / B / C**

波形上提供三个彩色标记：

- 绿色 **A**：参考区间起点
- 红色 **C**：参考区间终点
- 橙色 **B**：旁白插入位置（须位于 A 与 C 之间）

拖动时自动约束，B 无法移出 A–C 范围。也可在下方输入框直接输入时间码，支持 `1:23.456` 与 `83.456` 两种格式。

建议将 A–C 控制在 10–20 秒，区间应干净、连续，且为单人说话。

**3. 确认参考窗口**

右侧「音色参考窗口」显示实际使用的区间。若 A–C 超过 15 秒，程序会自动从中选取约 12 秒的最优区间（判据：削波最少、语音连续、尽量包含插入点），波形上以绿色高亮标出。

如需确认该段内容，点击「🗣 识别参考片段在说什么」，程序将转写该段文字。建议执行此步以核对语气。

**4. 输入旁白**

填写待合成的文本。数十字最为稳定。

**5. 生成**

点击「🍞 开始夹」。

- **首次运行需等待 1–2 分钟**，用于加载模型
- 后续每次约 **20–30 秒**；模型进程常驻，无需重复加载

**6. 验收**

结果区提供四个文件：

| 文件 | 用途 |
|---|---|
| 成品 wav | 直接导入剪辑软件 |
| 成品 mp3 | 试听与分发 |
| 单独旁白（匹配版） | 响度已与原始素材对齐的旁白，供手动拼接使用 |
| 单独旁白（48k 标准版） | 48k 单声道 / −16 LUFS 的通用交付规格 |

另附一份**回读质检报告**：将旁白转写为文本后与输入稿逐字比对，给出相似度百分比与差异对照表，读字错误在此体现。

> 判定前应先查阅差异表：语音识别自身也可能产生误判，差异不等同于合成错误。

## 参数说明

界面参数的调整建议如下：

| 选项 | 默认 | 说明 |
|---|---|---|
| **自动精选参考窗口** | 开 | A–C 超过 15 秒时自动选取最优 12 秒。**建议保持开启。** 关闭则以整个 A–C 区间为参考，过长会引入语气混杂 |
| **测量两边语速** | 关 | 量出参考片段与旁白各自的语速，并给出一个建议的滑条值。只测量，不重生成，代价是多十几秒 |
| **整体响度统一** | 关 | 默认策略为旁白响度对齐原始素材，原声不做任何改动，插回原视频时电平连续。开启后改为将整个成品标准化至 −16 LUFS |
| **回读质检** | 开 | 生成后执行语音识别比对。无需时可关闭以节省时间 |
| **语速** | 1.00 | **往右更快，往左更慢**（0.7 明显放慢，1.4 明显加快）。1.00 是模型自己的节奏，多数情况够用 |
| **输出范围** | 夹心 | 夹心 = A→B + 旁白 + B→C；整条 = 0→B + 旁白 + B→结尾。需保留完整原文件时选择「整条」；只合成旁白 = 只念一遍并单独导出，不碰原声 |

### 语速该往哪边拉

试过让程序自动对齐：先按原速合成一版，测出它和参考片段的语速差，
再按系数重生成一遍。系数算得很准 —— 实测对齐后旁白 4.960 字/秒、
面包 4.957 字/秒，残差 0.1%（`duration_factor` 在模型里是线性的，
`target_lengths = codes × 1.72 × duration_factor`，一次就能校准）。

但**听感并没有变好**，代价却是合成时间翻倍（同一份稿子 163 秒 → 622 秒）。
所以自动对齐已撤掉，改成滑条手动调。需要参考值时勾选「测量两边语速」，
结果里会给出建议值。

测量按 **字数 ÷ 窗口总时长** 算，也就是**含换气与停顿**。这一点有讲究：
实测发现去掉静音后的吐字速率，旁白和面包只差 1%~4%（模型本来学得很像），
真正不一样的是**停顿占比**，差到 11%~18% —— 听感上的快慢正来自停顿。
所以滑条调的就是这个整体节奏。参考窗口里若大半不是语音（背景乐、环境声），
总时长是被污染的量，此时自动退回「仅发声」口径。

## 术语表

| 词 | 含义 |
|---|---|
| **A / C** | 采样区间的两端，界定作为参考的音频范围 |
| **B** | 插入点，新旁白在原始音频中的位置 |
| **采样区间** | A 到 C 之间的原始音频 |
| **参考窗口** | 实际输入模型的音频片段。A–C 过长时会自动截取其中一段 |
| **削波** | 信号超过最大电平被削平，表现为失真与爆音。数值越低越好 |
| **LUFS** | 响度单位，数值越接近 0 越响。广播交付常用 −16 |
| **loudnorm** | ffmpeg 的响度标准化滤镜 |
| **回读质检** | 用语音识别转写合成结果并与原文比对 |
| **MPS** | Apple 芯片的 GPU 计算后端，本项目用于加速推理 |
| **IndexTTS2** | 本项目的合成模型，B 站开源，不包含在本仓库中 |

## 常见问题

### 首次运行为何耗时较长？

需加载 3.2 GB 模型权重。后续每次约 20–30 秒；模型进程常驻，不会重复加载。

### 能否并发处理多个任务？

单任务。Apple GPU 上的推理不支持并发，界面会提示「上一次生成尚未结束」。

### mp3 未生成？

ffmpeg 缺少 `libmp3lame`，检查命令见第 1 步。wav 输出不受影响。

### 质检报告未生成？

whisper 未正确配置。检查 `bcb.local.env` 中的 `BCB_MLX_WHISPER` 与 `BCB_WHISPER_MODEL`。此项不影响合成。

### 合成结果不像原声或带有杂音？

优先检查参考素材质量：点击「识别参考片段在说什么」，确认未选中含背景音乐或电流声的区间，并改用 10–20 秒的干净区间重试。多数情况由样本质量导致。

### B 能否位于 A–C 之外？

不能。B 必须位于采样区间内部，此为设计约束。

### 支持的音频长度上限？

实测数十分钟可用。瓶颈在于浏览器上传与波形计算；模型的计算量仅与 A–C 区间长度相关。

### 如何更换端口？

在 `bcb.local.env` 中设置 `BCB_PORT=9000`。

### 出现未知错误？

模型进程的完整日志位于 `work/tts_server.log`，应优先查阅。

## 隐私与合规

### 仓库不包含任何使用数据

- **音频**：上传的录音、提取的音轨与合成旁白均存放于 `work/` 目录
- **模型权重**：由使用者自行下载，路径通过环境变量配置
- **个人路径**：所有本机绝对路径均定义在 `bcb.local.env`，该文件不纳入版本控制

`work/` 为最敏感目录，包含原始录音及其克隆产物。该目录默认已被 gitignore。发布或分发前建议确认：

```bash
git status --porcelain --ignored | grep '^!!'
```

该目录不应包含在任何对外分发的产物中。

### 使用边界

声音克隆具有明确的法律与伦理边界。IndexTTS2 的免责声明禁止：

- 合成政治人物、公众人物或**任何未经授权的个人**的声音
- 用于诋毁、侮辱、欺诈或身份盗用

本项目的前提是使用者对素材中的声音拥有合法权利，典型场景为补录本人旁白。以他人声音合成其未表述的内容，风险由使用者自行承担。

## 项目结构

```
server/           网页服务：任务调度、ffmpeg 封装、参考窗口选取、响度匹配、回读质检
  preflight.py      启动前自检，可独立执行
worker/           常驻合成服务，运行于模型自身环境（仅使用标准库）
web/              单页界面，无外部依赖，离线可用
iina/             IINA 播放器插件：在播放器内完成同一套操作（详见 iina/README.md）
bcb.env.example   路径配置模板
run.sh            启动脚本（含自检）
work/             运行时产物（已 gitignore，含隐私数据）
```

### IINA 播放器插件

除浏览器界面外，同一套能力也做成了 IINA 插件：面板位于播放器右侧边栏，
可直接读取正在播放的文件并打点生成，无需另外打开浏览器。
安装、使用与验收清单见 [`iina/README.md`](iina/README.md)。

### 环境隔离设计

系统分为三层环境，互不干扰：

| 层 | 环境 | 职责 |
|---|---|---|
| 网页与调度 | conda 环境 `bcb`（Python 3.11 + 四个包） | 界面、文件上传、ffmpeg 处理、任务调度 |
| 合成 | IndexTTS2 自带 venv | 加载模型、生成音频 |
| 质检 | 安装 mlx-whisper 的环境 | 转写与比对 |

网页层不安装任何 AI 相关包，通过本机 HTTP 与常驻的模型进程通信。该设计有两点原因：其一为依赖隔离，两侧对 Python 包版本的要求不同，混装易产生冲突；其二为模型常驻，加载一次约需一分多钟，而调稿过程会反复重新生成，每次重启进程都会引入等量额外耗时。

## 已知限制

- 参考片段含背景音乐、削波或长静音时，克隆质量下降。界面会给出警告，但不阻止执行。
- 上百字的旁白建议分段生成；模型对超长文本的稳定性弱于短句。
- 模型输出为 22050 Hz，将重采样至素材原始采样率。素材本身为低码率有损音频时，原声与旁白的质感存在差异。
- 依赖 IndexTTS2 的模型许可。权重受其自身许可约束，本仓库不包含任何权重。
